# 休息、日程、答案保留與週報

## 工作日／假日守門

先取得使用者時區與地區。預設週一到週五可學習，週末、公定休假與自訂休假休息。台灣只是可選 profile，不硬編碼到其他使用者。週六補班仍按預設週末休息，除非使用者明確改成跟隨補班表。

優先序：本次使用者明確自願學習 → 自訂休假 → 已確認公定休假 → 每週學習日。單次自願不改永久排程，不自動授權寄信、清理或通知。

使用官方假日資料或使用者指定 Calendar，記錄來源、涵蓋期間、查核時間與假日類型；一般節慶不自動當國定假日。無法確認某日是否休假時，將自動推送標為 pending_calendar_verification，暫停該日主動寄信、提醒及排課，讓使用者仍可手動學習。不可猜測「不是假日」。

所有主動工作共用守門：Email、複習提醒、Calendar 課程、週報及清理。休息日不打卡、不算缺課、不累積懲罰性補課；到期複習保留但後續按容量消化。可在每週最後學習日維護未來 90 天假日表；每次實際執行前仍重新檢查。

## 預設時段（使用者当地時間，可替換）

| 工作 | 時間 | 限制 |
|---|---|---|
| 每日教材 | 08:30 | 同一 Day 只成功寄送一次；未讀不等於完成 |
| Spaced Review | 20:20 | 5–10 分鐘；只在學習日主動提醒 |
| 正課 | 20:30–21:10 | 40 分鐘；先檢查既有衝突 |
| Weekly Learning Report | 週五 21:20 | 若休假，改本週最後允許學習日的課後 |
| Holiday guard / 清理 | 學習日的維護時段 | 不在完整休息日主動觸發 |

週報涵蓋當地週一至週日，註明生成截止時間。週五休假時星期四課後產生；若整週休假則不生成空週報，在下次學習時提及即可。課程尚未結束時可產生標明「截至目前」的報告，之後以同一 report_id 更新；不要虛構尚未發生的結果。手動額外學習也可更新同一週報。

Calendar 優先排有限期間內已核對的學習日，或使用確定支援排除日期的重複事件。排程不硬綁 Day 編號；標題用主題＋學習時段，開始時查 session。假日變動只調整系統所建事件，不刪除他人行程。存在衝突就提出可用替代時段，不自動覆蓋。

## Day 與日曆日期

以 session 狀態解析：有 in_progress 就接續；否則取最小的尚未完成 Day。提前完成 Day 8 後，下次為 Day 9；相同日期可完成 Day 7、8，兩筆獨立 session。隔天排程再次查狀態，不重發 Day 8。提前進入的 Day 若尚無教材，就在對話交付；若已送過教材，不再寄第二封。

排程事件不等於學生出席。未出席不增加 Day，也不自動判課程失敗。重跑相同工作用穩定 idempotency_key 防重複。兩個執行者同時啟動時，以狀態版本／鎖控制；無此能力則序列執行並在寫入前重讀。

## 答案延遲清理

答案暫存檔自成功建立且提供使用者存取的 `published_at` 起算 **72 小時**。`expires_at = published_at + 72h`，時間戳含時區或 UTC，不能用「第三個工作日」代替。若 72 小時後為休息日，於下一個允許維護時段處理；介面要寫「至少保留 3 天，假日順延清理」。

僅限登記在 artifact registry、kind=temporary_answer、由本系統建立、位於設定的答案資料夾且未 pin 的資源。外部 hook 啟用時先取得這項保留政策的授權並記錄；單純使用 skill 不代表允許刪檔。預設 cleanup.enabled=false。已授權後不用每次重問。

流程：列出 registry 中已到期候選 → 重讀精確資源 ID、擁有者／系統標記、根目錄與 pin 狀態 → 確認不是錯題／複習／原始作答 → 優先移垃圾桶或受管理 archive → 確認結果 → 寫 audit。禁止萬用字元或刪整個資料夾。成功前不記錄 deleted；結果未知先查狀態，最多重試兩次，再標 failed 待處理。

這是減少答案檔堆積的政策，不是完整資料抹除。已寄出的郵件、學習者副本與每日複習裡的必要解題說明不清除。清理後舊 Check answers 可能失效；教材應事先註明期限，學習者可回對話依原題重新產生答案並記為新版本，不能假稱舊連結仍有效。
